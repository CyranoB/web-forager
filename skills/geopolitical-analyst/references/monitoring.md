# Monitoring baseline and updates

Use the prior baseline supplied in this conversation or the user's designated artifact.
If no baseline is available, establish a first-run baseline; do not invent a prior
assessment or claim that something changed since an unknown cutoff.

Record a compact baseline containing:

- the research cutoff, question, actors, geography, and horizon;
- material judgments, confidence, dated supporting evidence, and source links;
- each indicator's definition, current status, observation date, and the threshold
  that would trigger reassessment;
- unresolved evidence gaps and the conditions that could change the judgment.

For an update, compare new evidence against those recorded observations and thresholds.
Distinguish an event occurring after the prior cutoff from an older event newly found
in research. If disclosure of an older event is itself material and new, report both
the disclosure date and underlying event date. Preserve uncertainty about either date.
State which indicators changed, whether thresholds were crossed, and the reason for
any revised judgment or confidence. Missing new evidence is not proof of stability.

Maintain the updated baseline in conversation state by default. When the user requests
persistent monitoring state and designates an artifact, update that artifact with the
new cutoff, evidence, judgments, and indicators. Do not create scheduled jobs or send
notifications merely because an analytical update was requested.

**Complete when:** a first run has an explicit dated baseline, or an update is traceable
to an available prior baseline; event changes and newly discovered evidence are
separated, confidence changes are explained, and unresolved limits are visible.
Report material changes without repeating unchanged background.
