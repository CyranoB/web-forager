# Domain docs

This repository uses a single-context layout: root `CONTEXT.md` for domain
terminology and `docs/adr/` for architectural decisions.

Before exploring the codebase, read the root context and ADRs relevant to the work.
When these documents are absent, proceed silently; the domain-modeling skill creates
them as terminology or decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests. When a needed concept
is absent, reconsider the term or note the gap for domain modeling.

If a proposal conflicts with an existing ADR, name the ADR and explain why the
decision should be revisited.
